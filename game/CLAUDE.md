# CLAUDE.md

このファイルはプロジェクトの常設ルールブック。毎セッションの最初に読み、これに従うこと。
詳細な仕様は `SPEC.md` を参照。

## プロジェクト概要

- 2D 横スクロールのアクション・アドベンチャー（ストーリー進行あり）。
- **アクションは常時の柱**。戦闘だけでなく探索・移動にもアクションを使う。操作感を最優先。
- 目標: web で公開できる「遊べる」完成度。まず縦の断面（SPEC.md 6章 / M0→M3）を作る。

## 技術・環境

- エンジン: **Godot 4.x（インストール済みバージョンに合わせる）**。
- 言語: **GDScript、静的型付けを徹底**（`var x: int` / 戻り値・引数の型注釈）。
- 公開ターゲット: **Web（HTML5）が第一**。デスクトップは確認用。
  - Web エクスポートは早期に一度通す。Web で動かない書き方（重い同期処理、非対応API等）を避ける。
- レンダリングは**非ピクセルアート前提**：viewport 1920×1080、stretch=`canvas_items`/`expand`、テクスチャフィルタは**リニア**。nearest にしない。

## 実行・確認

- ローカルはデスクトップ実行で確認、公開前に Web 書き出しで確認。
- 各マイルストーン末で**必ず動く状態**にする。壊れたまま次に進まない。

## ディレクトリ

`SPEC.md` 3章の構成に従う（`scenes/ scripts/ data/ assets/`、Autoload は `scripts/autoload/`）。

## コーディング規約

- ファイル名: `snake_case.gd`。クラス／ノード名: `PascalCase`。`class_name` は再利用する型に付ける。
- **キー入力は Input Map のアクション経由**（`move_left` 等）。キーコード直書き禁止。
- 調整値（速度・重力・ダメージ・クールダウン等）は **`@export`** でエディタから触れるように。マジックナンバーをコードに埋めない。
- ノード間連携は基本 **signal**。密結合の直参照を避ける。
- パスやリソースIDをハードコードしない。データは `data/` に置き、コードは**未知のID/欠損データでも落ちない**よう防御的に書く。
- コメント・ログは日本語で可。

## アーキテクチャ規約

- グローバルな状態・仕組みは **Autoload**（`GameState` / `SceneManager` / `DialogueManager` / `AudioManager`）に集約。1 つの Autoload に 1 つの責務。
- プレイヤーは **ノードベースの FSM**（Idle/Run/Jump/Fall/Dash/Attack/Hit）。新アクションは状態追加で拡張。
- 見た目は **`AnimationTree`（StateMachine）** で FSM 状態に紐づける。**ゲームロジックとビジュアルを分離**し、アート差し替えでロジックを壊さない。
- 物理レイヤは `SPEC.md` 2章の表に従って命名・運用（world/player/enemy/hitbox/hurtbox/interactable）。

## コンテンツ／分担

- **シナリオ・セリフ・イベントの中身は人間（作者）が書く。物語内容を勝手に創作・改変しない。**
- 会話は `data/dialogues/*.json`（SPEC.md 8章のスキーマ）。作者が JSON だけで会話を追加できる状態を保つ。
- Claude が担うのは「器・仕組み・システム」。

## 進め方の作法

- 大きなリファクタ・設計変更・依存追加は**着手前に一言確認**。
- まとまった単位でコミットし、コミットメッセージは何をしたか簡潔に。
- 迷ったら `SPEC.md` の該当章を確認。仕様に無い判断が要る時は聞く。
