# ゲーム仕様書 v0（縦の断面 / Vertical Slice）

> このドキュメントは Claude Code への実装指示を兼ねる。
> まず「6. 縦の断面で作るもの」を M0→M3 の順に実装すること。
> 全体を一気に作らない。各マイルストーンで**動く状態**を維持する。

---

## 1. 概要・ゲームの柱

- ジャンル: 2D 横スクロール（横固定は必須でない）アクション・アドベンチャー。
- 進行: ストーリー／イベントも横スクロール空間の中で進む。
- 柱（設計の優先順位）:
  1. **アクションは常時の柱**。戦闘だけでなく**探索・移動そのものにアクションを使う**。動きの滑らかさと操作感を最優先で担保する。
  2. ストーリー／会話／イベントで進む。
  3. web で気軽に公開できる規模の「遊べる」完成度を目指す。
- 分担: シナリオ・セリフ・イベントの中身は**人間（作者）が担当**。エンジン・システム・仕組みは Claude 主導、作者が修正。→ 会話やイベントの「中身」は**データとして分離**し、コードを触らず書けるようにする（8章）。

## 2. 技術スタック・エンジン設定

- エンジン: **Godot 4.x（4.3 以降、最新安定版）**。インストール済みバージョンに合わせること。
- 言語: **GDScript（静的型付けを徹底）**。
- 公開ターゲット: **Web（HTML5 書き出し）を第一**。デスクトップ書き出しは動作確認用。
  - Web エクスポートは**早い段階で一度通す**（後で詰まらないため）。SharedArrayBuffer 周りの制約に注意。公開先は itch.io を想定。
- レンダリング（**非ピクセルアート前提**）:
  - 基準解像度: **1920×1080（16:9）**。
  - Stretch: mode = `canvas_items`, aspect = `expand`。
  - テクスチャフィルタ: **リニア（滑らか）**。※ピクセルアートではないので nearest にしない。
- 入力: **必ず Input Map のアクション経由**。キー直書き禁止。定義するアクション:
  `move_left`, `move_right`, `jump`, `attack`, `dash`, `interact`, `pause`。
  - 将来ゲームパッド対応を想定し、アクションに複数の入力を割り当てておく。
- 物理レイヤ（衝突マスク管理。番号は例、`project.godot` で名前を付ける）:
  1. `world`（地形）
  2. `player`
  3. `enemy`
  4. `player_hitbox`（攻撃の当てる側）
  5. `enemy_hitbox`
  6. `hurtbox`（食らう側）
  7. `interactable`（調べる・話す対象）

## 4. アーキテクチャ

- **Autoload（シングルトン）**:
  - `GameState`: ストーリーフラグ、進行状態、プレイヤーの永続ステータス、セーブ/ロード。
  - `SceneManager`: ルーム間遷移（フェード付き）、遷移時のプレイヤー状態の受け渡し。
  - `DialogueManager`: 会話データ（8章の JSON）を読み込んで DialogueBox に流す。終了時フックで `GameState` のフラグを立てる。
  - `AudioManager`: BGM/SE の再生窓口（後回し可、枠だけ用意）。
- **Player**: `CharacterBody2D` + **ノードベースの有限状態機械（FSM）**。
  状態: `Idle / Run / Jump / Fall / Dash / Attack / Hit`。
  各状態は独立スクリプトにし、遷移条件を明示。将来アクションを増やしやすくする。
- **アニメーション駆動**:
  - 見た目は **`AnimationTree`（StateMachine ノード）** で駆動し、プレイヤー FSM の状態にマップする。
  - **アート最終ターゲットはベクター/手描き＋スケルタル（Skeleton2D）アニメ**（11章）。
  - **着手時はプレースホルダ**（`ColorRect`／単色 `Sprite2D` ＋当たり判定ボックスの可視化）。
  - ゲームロジック（FSM）とビジュアル（AnimationTree＋リグ）を分離し、本番リグ差し替えで作り直しが出ないようにする。
- **疎結合**: ノード間はできるだけ **signal** で連携。直参照の依存を減らす。
- `@export` で調整値（物理・ダメージ等）を全部エディタから触れるようにする。

## 5. コンテンツはデータ駆動（分担の肝）

会話・イベント・フラグは**データとして分離**する。エンジンはデータを読むだけ、作者はデータ（台本）を書くだけ。8章にスキーマ。

## 6. 縦の断面で作るもの（機能一覧）

1つの小さなエリアで、全コアシステムを1回ずつ通す。

- プレイヤー: 歩く／走る／可変ジャンプ／**ダッシュ（＝探索アクションの1つ）**。
- 探索アクション: ダッシュで隙間を越える等、**移動にアクションが要る地形**を1つ用意。
- 戦闘: 攻撃1種、ヒットボックス／ハートボックス、敵1体（巡回＋接近攻撃の簡易AI）、HP・ダメージ・撃破・被弾・リスポーン。
- インタラクト: オブジェクトを調べる、NPC 1体と会話（データ駆動）。
- 会話・フラグ: 会話終了で `GameState` のフラグが立ち、閉じてた扉が開く等の因果を1つ。
- 遷移: エリアA→エリアB へシーン遷移（プレイヤー状態を保持）。
- セーブ/ロード: 現在ルーム＋フラグ＋ステータスを `user://` に保存、起動時ロード。
- UI: HP 表示（HUD）、ポーズメニュー（最低限）。

これが動けば「量産すれば完成」の形になる。

## 7. プレイヤー操作・アクション仕様（`@export` で調整可能に）

初期値の目安（すべて調整前提）:

- 歩行速度: 200 px/s、走行: 320 px/s
- 重力: 1500 px/s²、最大落下速度: 900 px/s
- ジャンプ初速: 520 px/s、**可変ジャンプ**（ボタンを離すと上昇カット）
- コヨーテタイム: 0.1s、ジャンプ入力バッファ: 0.1s
- ダッシュ: 速度 600 px/s、持続 0.18s、クールダウン 0.4s、ダッシュ中は無敵フレーム任意
- 接地・壁判定は `CharacterBody2D` の `is_on_floor()` 等を使用

操作感（キビキビ感）を最優先。数値は後で詰める前提で、まず気持ちよく動く土台を作る。

## 8. 会話・イベント・フラグ（データ形式）

会話は `data/dialogues/*.json`。スキーマ例:

```json
{
  "id": "villager_intro",
  "lines": [
    { "speaker": "村人", "text": "……よく来たね。" },
    { "speaker": "村人", "text": "この先は危ない。気をつけて。" }
  ],
  "choices": [],
  "on_end": { "set_flags": ["met_villager"] }
}
```

- `speaker` / `text` の連なりで基本の会話。
- `choices`（任意）: `[{ "text": "…", "goto": "dialogue_id" }]` で分岐（縦の断面では未使用でも枠は用意）。
- `on_end.set_flags`: 会話終了時に `GameState` へ立てるフラグ。
- イベントのトリガーは `Area2D`（`interactable` レイヤ）に dialogue の `id` を持たせる形。将来はイベントスクリプトに拡張。
- **作者は JSON だけ触れば会話を追加できる**こと。コード側は「未知の id でも落ちない」よう防御的に。

## 9. シーン遷移／セーブ・ロード

- 遷移: `SceneManager.change_room(room_path, spawn_point)`。フェードアウト→ロード→スポーン地点配置→フェードイン。プレイヤーの HP 等は保持。
- セーブ: `GameState.save()` が現在ルーム・スポーン・フラグ辞書・プレイヤーステータスを `user://save_0.json` に書く。`load()` で復元。起動時に存在すれば読む。
- 縦の断面ではオートセーブ地点1つ＋手動セーブ1つで十分。

## 10. UI / HUD

- HUD: HP 表示（数値かバー、後で差し替え可）。
- DialogueBox: 話者名＋本文、送り操作（`interact`）。
- PauseMenu: `pause` で開閉、再開・（後で）設定。

## 11. アート方針

- **最終ターゲット**: 非ピクセルの手描き/ベクター系ビジュアル ＋ **スケルタル（ボーン）アニメ**（Ori / Hollow Knight 系の方向）。滑らかで視認性が高く、アクションと相性が良い。素材総量も frame-by-frame より小さい。
- **着手**: プレースホルダ（単色図形＋当たり判定の可視化）で全機能を作る。
- **差し替え設計**: ビジュアルは `AnimationTree` 経由で FSM 状態に紐づけ、本番リグへの差し替えでロジックを壊さないこと。
- ピクセルアートには**しない**（フィルタ・解像度設定を非ピクセル前提で統一）。

## 12. マイルストーン

- **M0**: プロジェクト骨組み。Autoload 空実装、Input Map、物理レイヤ、1ルーム、プレイヤーが歩く/走る/ジャンプ/ダッシュ。**Web エクスポートを一度通す**。
- **M1**: 戦闘。攻撃・Hitbox/Hurtbox・敵1体・HP/ダメージ/撃破/被弾/リスポーン。
- **M2**: 会話・インタラクト・フラグ。DialogueManager＋JSON、NPC 会話、フラグで扉が開く因果。
- **M3**: ルーム遷移＋セーブ/ロード＋HUD＋ポーズ。→ **縦の断面 完成**。
- M4 以降: コンテンツ量産（ルーム・敵・会話追加）、探索アクション拡張、アート差し替え。

## 13. 分担・運用ルール

- シナリオ・セリフ・イベントの**中身は作者が書く**。Claude は勝手に物語内容を創作・改変しない（データの器と仕組みを作る）。
- 大きめのリファクタや設計変更は**着手前に一言確認**。
- 各マイルストーン末で**必ず動く状態**にしてコミット。

## 14. 最初にやること（Claude Code への初手）

1. Godot 4 プロジェクトを 2〜3 章の設定で初期化（viewport / stretch / filter / Input Map / 物理レイヤ名）。
2. 3 章のディレクトリを作成。
3. Autoload 4 つを空実装で登録。
4. `Room_01.tscn` と `Player.tscn`（CharacterBody2D＋FSM＋プレースホルダ）を作り、**歩く/走る/ジャンプ/ダッシュ**まで実装（M0）。
5. Web エクスポート設定を入れて一度書き出しを通す。
6. ここまでで一旦動かして確認 → M1 へ。
